# 写一个新风格

没有现成风格合适时，就原创一个，存成 `styles/ours/<英文目录名>/STYLE.md`，再在 `styles/INDEX.md` 里登记一行。

一份风格规格只写“这个风格在任何一支片子里都成立的东西”，不写某一支片子的故事、镜头表、时长。片子的具体内容放进那支片子的 TREATMENT.md。

## 结构（按这个顺序写）

```
# 中文名 · English Name — Style Prompt

> 两三句：这个世界是用什么材料做的，它在画面上怎么动。
> 参照（只学语法）：从哪些传统、工艺、作品里学什么；不拿什么。

## 1. 它是什么，它不是什么
一眼认出这个风格的 3–5 个特征；最容易混淆的几个风格，以及分界线。

## 2. 招牌时刻
只有这个媒介做得到的动作，每条写：是什么 + 适合什么样的歌词或情绪。
（放在前面，因为它决定了片子的高潮长什么样）

## 3. 材质与渲染
用代码怎么模仿这种材料：Canvas 2D 还是 WebGL、分几层、纹理怎么做、光怎么打、哪些要固定种子防止“沸腾”。

## 4. 色彩
规则，不是一张色板：底色是什么、强调色留给谁、全片唯一不变的颜色是什么、什么时候可以换色。

## 5. 字与歌词
歌词以什么形态出现（竖排、贴纸、字卡、旁白框……），用哪些 OFL 字体，怎么进场、怎么退场。

## 6. 动作
什么东西会动、怎么动（每帧平滑还是两拍一动）、什么东西绝对不动。

## 7. 镜头与转场
一张表：镜头 | 表达什么 | 用在哪里。再写转场的语法（这个媒介自己的转场是什么）。

## 8. 与歌配合
主歌、预副歌、副歌第一拍、桥段、静音、结尾，在这个风格里分别怎么处理。

## 9. 常见坑
用代码做这个风格最容易翻车的地方，以及怎么避免。

## 10. 引擎计划
需要哪些绘制模块（例如 paper.js、ink.js），每个做什么。

## 11. 变化空间
几种不同的结构、开场、结尾，避免每支片子长得一样。
```

写完之后，先用它渲染 3 张风格帧，看不对就回来改规格，而不是硬做。
