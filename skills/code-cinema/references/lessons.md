# 制作经验

做片子时反复踩过的坑和有效的做法。新片子开工前读一遍；有新经验就追加。

## 创意与结构

- **永远先要歌词原稿。** whisper 的转写会有错字，而且可能漏句；原稿为准，whisper 只借时间。
- **意象，不是图解。** 逐句把歌词画出来（唱到什么画什么）是科普视频的逻辑，不是 MV。用一个核心意象贯穿，让它变化、升级。
- **剪辑跟着歌呼吸。** 主歌长镜头，副歌第一拍闪白进入最强的画面，桥段给一口长气，尾声回到开头的物件。全片一个速度是最常见的失败。
- **副歌重复时升级，不要复制。** 同一套镜头结构，逐次加码，既有记忆点又不无聊。
- **静音是标点。** 歌里有完全静音的一拍时，给纯黑加一个逐渐变大的光点，或者一个静止的画面。
- **有角色的风格先做姿态测试。** 代码画的全身人体容易像木偶；用特写（眼、手）、逆光剪影和拍点上的姿态定格撑起全片，全身只出现一瞬间。
- **歌词版式跟着风格走。** 字层可以完全自定义（`FILM.drawText` 返回 true）：竖排进构图、按拍贴上再烧掉的符纸、漫画旁白框等；关键句居中大字。

## 歌词对齐

- 副歌重复段 whisper 容易听错：用最可靠的一遍副歌行做**结构模板**（每句相对副歌起点的偏移），校正其他几遍，误差可以压到 0.3 s 内。
- `file://` 页面里 `fetch()` 读不了本地 JSON：把 `lyrics.json` 转成 `lyrics.js`（`window.LYRICS`）。

## 渲染与画面的坑

- Voronoi 焦散像网格或裂纹：边缘要软，加光池衰减，不要铺满全屏，出场别太多次。
- 离散采样的 bloom 在细亮线上出条纹：改用 mipmap 模糊。
- 在页面里画颗粒会让文件暴增（可到 1 GB 以上）：颗粒放进 ffmpeg（`--grain`）。
- 亮背景上的白字看不见：大字加阴影。
- 规整的四格窗户光斑像某个操作系统的标志：边缘要软，只留一根窗棂。
- 文字层纹理设了 mipmap 过滤却没生成 mipmap，会返回不透明黑，整帧全黑。
- 离屏画布里画整个场景再缩放贴进画面时，场景自己的光照函数若用 `setTransform(1,0,0,1,0,0)` 会盖满全屏：先画到离屏 canvas 再 `drawImage`。
- 用两个 rect 拼“画框”时，nonzero 填充会把中间也填上：分成四条画，或用 evenodd。
- 竖排招牌字号要按 `min(w, h)` 算。
- 相机推近时要锁住主体的实际世界坐标，不然会把脸推出画面。
- 剪影必须先画到离屏 canvas 再整体加 `shadowBlur`，否则每个部件各自发光，像线框。
- 汉字多的大字：描边加挤出后会糊成一团，改用粗明朝 + 细描边、不加排线；极粗的黑体只留给少量假名拟声字。

## 渲染速度

- 3–4 分钟的 1080p 片子，8 路并行浏览器在 Apple 芯片上大约 3–7 分钟渲完；成片通常几十到一百多 MB（`--grain 2`）。
