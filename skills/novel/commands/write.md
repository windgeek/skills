# write 命令详细规则

> 从 SKILL.md 拆出。每次写章（`/novel write`，或自动决策走到第 8 步）都先读本文件，按顺序执行。

1. **加载上下文**（分层加载，控制总量）：

**Tier 1 — 必读核心**（每章必加载）：
- `novel/meta.yaml`
- `novel/outline/volume_XX.md` **节拍表**（文件头部约30行；逐章详细描述按需在 Tier 3 加载）
- `novel/world/geography.md` **核心城市和地标速查**（防止地点穿帮——地名错误一旦发布无法修复）
- `novel/continuity/character_state.md` 顶部硬属性速查表 + 对白风格速查表（读到第一个角色详情之前——速查表是写对话时角色不串味的关键）
- `novel/continuity/log.md` 摘要区 + 最近 3 章详细记录——**额外提取前 3-5 章中所有未来时承诺**（"周X见""改天""下周"等约定），列为待核查清单，在 Step 2 章节规划时逐条对齐本章时间
- `novel/continuity/foreshadowing.md` 核心设定锁定区 + 硬种子待埋清单 + 全局活跃索引（所有 OPEN/PARTIAL 条目）。伏笔详情按需从 `foreshadowing_archive/vXX.md` 加载（Tier 3）

**Tier 2 — 规划后加载**（Step 2 确定出场角色后再读）：
- 前 1 章正文**结尾约 60-80 行**（只读尾部，保持文风衔接；log.md 详细记录区已含剧情信息，无需读全文）
- 本章出场角色在 `character_state.md` 中的完整状态块和最近增量

**Tier 3 — 按需加载**（写作中发现需要时才读）：
- 大纲逐章详细描述（按节拍 ID 定位到对应段落，不读整卷）
- 更早章节正文、`log_archive/` 归档文件
- `novel/continuity/timeline.md`
- 角色 character yaml（仅需回顾说话风格或首次出场时）
- `novel/world/rules.md`

2. **章节规划**：
- 对照节拍表确认本章将消化哪些节拍（记录节拍 ID）。**漂移阈值（双层）**：偏差≥3 章=警觉信号，必须在规划阶段说明原因并标注；偏差≥5 章=必须先停下执行 `/novel outline sync N` 校准后再写
- 列出本章出场角色（含被提及的未出场角色），对照 `character_state.md` 顶部**硬属性速查表**确认代词和称谓
- 确定本章故事内时间
- 确定本章场景/地点
- 确定本章核心事件和爽点
- 确定章末钩子

3. **正文写作**：
- 章节格式参考 [../templates/chapter_template.md](../templates/chapter_template.md)
- 章节标题和文件命名的规则见校验项 J
- **标准小说正文格式（强制）**：
  - 正文场景切换用空行 + 时间/地点/动作句自然转场，如"周二上午。""晚上十点多。""回到工位时……"
  - **空白层级**：普通段落之间保留 1 个空行；真正换场/换时段/换地点时，在转场句前插入一行只含全角空格 `　` 的空白段，形成稳定软切场（Markdown/网页不会折叠），不要使用横线或符号
  - **禁止**用 `---`、`—————`、`* * *`、小节标题、Markdown 分割线做章内场景分隔；这些只属于草稿/文档，不属于番茄小说正文
  - 正文中禁止出现 `c020`、`B12`、`伏笔#`、`节拍`、`log`、`character_state` 等工程标记；需要提及过去事件时，用故事内语言自然回忆
  - 除角色真实写在手机/电脑里的记录外，正文不要使用列表、表格、项目符号；即便写备忘录，也要让它像角色在写，不像设定文档
  - **段落节奏**：短段落服务阅读节奏，不等于每句话单独成段。连续动作、同一心理判断、同一画面描写应合并成自然段；只有对白、强停顿、反转、命名、章末钩子可以单句独立成段
  - 章节 frontmatter 可以保留 Markdown/YAML，但正文从 `# 第X章` 以下必须按小说排版
- 严格保持角色说话风格（写对话前先回顾角色yaml中的speech段）
- 注意节奏：场景切换不超过 3 个/章
- 对话和叙述交替，不要大段独白
- **章末必须有钩子**，类型包括但不限于：
  - 悬念钩子：揭示一个新问题或异常（"那个声音又响了"）
  - 反转钩子：推翻前面建立的认知（"他说的全是假的"）
  - 情感钩子：角色关系发生微妙变化（"她第一次叫了他的名字"）
  - 期待钩子：明确下一步要做什么（"明天，去找老周"）
  - 信息钩子：给出一条让读者想知道后续的信息碎片
  - **预警钩子**：社会面/环境面出现异常信号（角色未察觉或归因为巧合），但读者感知到世界正在变化（如医生闲聊时提到的怪病例、新闻里一行小字、报纸边角的失踪报道）
  - **结构钩子**：用于段落/单元/卷的收束——不抛新悬念，给一个阶段性的情感回响或意象（适用于卷尾、案件弧结束、长段落收束）

4. **写后更新**（这一步绝对不能跳过）：
- **字数核算（必须用命令实测）**：写完正文用 `wc -m novel/chapters/v0X_cXXX.md` 取字符数，扣除 frontmatter ≈200 字符后即正文字符数；不足 4500 字必须扩写；**若正文字数超过 18000 字必须精炼去冗余，若超过 19500 字强制修剪至 18000 字以内，绝对禁止踩 20000 字平台硬上限**；核算完成后**更新章节 frontmatter 的 `word_count`**
- 更新 `novel/continuity/log.md`（每章 log **≤30 行**——关键事件、状态变化、伏笔、钩子各用精简条目，不逐句复述剧情）。**插入位置规则**：最近章节详细记录区按章号**降序**排列，新章节直接插到 `## 最近章节详细记录区` 标题正下方
- 更新 `novel/continuity/character_state.md`：**只记增量 diff**——本章未变化的字段不重复写；"最后出场"和"已知信息"必须更新
- 更新 `novel/continuity/foreshadowing.md`（**双侧同步**，缺一不可）：
  a) **伏笔列表**：新埋/推进/回收的条目更新状态和备注
  b) **硬种子待埋清单**：若本章埋入了清单中的某项，在该项打 ✅ 并标注"cXXX 已埋: 简短说明"，同时去伏笔列表对应编号条目更新"实际埋设/回收"字段——两份记录互为印证
  c) **链式伏笔进度区**（顶部）：递进式系列伏笔（如异能觉醒链 F01→F02→F03→F04）除了单条 OPEN 状态，还要在该区更新链组进度可视化条
- 更新 `novel/continuity/timeline.md`：时间推进
- 更新 `novel/stats.md`：字数统计——**总字数必须用命令自动累加**：`wc -m novel/chapters/*.md | tail -1`，避免手算累计漂移；然后把累加值写入 stats.md
- **检查本章钩子是否明确**：在 log.md 的"章末钩子"字段写清楚钩子内容和类型
- 更新大纲节拍表：标记本章消化的节拍为 ✅，填入"实际"列章节号；若本章未消化任何预期节拍或消化了计划外的节拍，在节拍表下方备注原因

5. **写后强制校验清单**（逐项过，任何一项不通过必须立刻修）：

**A. 时间线算术校验**
- 本章元数据的 `story_time` 天数是否与上一章衔接？
- 本章中任何"还有X天"/"X天前"的对白/叙述，用绝对天数验算是否正确
- 涉及年份的台词（"X年前"），用出生年/事件年做减法确认

**B. "最后出场"全量扫描**
- 本章所有出场角色（含只说了一句话的），其 `character_state.md` 的"最后出场"字段必须更新为本章
- 每个出场角色必须有本章增量记录（哪怕只是一行"在场，无新变化"）

**C. 已知信息边界检查**
- 本章是否有角色获得了新信息？→ 更新该角色的"已知信息"
- 信息来源是否合理？（角色不在场时不能获知闭门对话内容）
- "对XX隐瞒的"字段：本章是否有新的隐瞒或隐瞒被打破？

**D. 伏笔状态同步**
- 本章是否触发了 foreshadowing.md 中任何 OPEN 伏笔？→ 改为 PARTIAL 并更新备注
- 本章是否完全回收了任何伏笔？→ 改为 CLOSED
- 本章是否新埋了伏笔？→ 新增条目
- 时序修复表中的"下一节点"是否需要更新？（已过的节点打 ✅，写错的章节号修正）

**E. 章节正文与连续性文件交叉比对**
- log.md 中引用的对白是否与章节正文完全一致？（不能凭记忆改写）
- 角色的物理描述（伤口、衣着、持有物品）是否与 character_state 一致？
- 正文中人称代词（他/她）和亲属称谓（姐姐/弟弟/妹妹等）是否与 `character_state.md` 顶部硬属性速查表一致？——死者和回忆中角色尤其容易出错

**F. 地理一致性校验**（地名错误一旦发布无法修复，必须逐项过）
- 正文中出现的所有**城市名、区名、街道名、地标名**是否与 `geography.md` 中的设定一致？
- 用 grep 搜索正文中所有地名，逐一核对：不能出现设定城市以外的地标（如故事设定在 A 城，却写出了 B 城才有的街区和地标）
- 城市人口、气候、方言、饮食等背景细节是否符合设定城市？（人口量级、气候、方言要和设定城市对得上）
- 角色的通勤路线、面试地点、学校位置是否在设定城市的合理范围内？

**G. 新设定首次出现锁定**（一旦发布无法修复，必须在写后立即锁定）
- 本章是否首次出现新地名（城市/区/街道/医院/楼盘/山名等）？→ 必须写入 `world/geography.md` 锁定（含交通/医疗/方言等关联属性）
- 本章是否首次出现新命名角色（即便只是龙套）？→ 按 [character 命令的"入选规则"](character.md)分级处理（主要角色建 yaml，活跃配角入 character_state，一次性龙套仅 log 备注）
- 本章是否首次出现新道具/术语/组织/势力/功法？→ 写入对应 `world/*.md` 文件
- **锁定原则**：首次出现即定性。设定细节一旦写入正文就形成锁，后续章节必须服从——错过锁定环节，下一次该地名/角色再出现时极容易自相矛盾

**H. 悬置约定一致性 + 场景不可替代性**
- 扫描前 3-5 章 log/正文中所有"未来时承诺"（约见面、约电话、约交付、"下周X"、"改天"等）。本章故事时间是否覆盖了某条约定的到期日？→ 正文中必须体现：履约 / 显式改期（含原因） / 显式取消。**沉默跳过 = 硬冲突**
- 逐个审视本章每个自然场景段落，一句话说出其不可替代功能。说不出 → 考虑合并或砍掉。与前 5 章存在结构雷同的场景（同类聚餐、同类面试被拒、同类争吵）→ 必须压缩为概述或合并，不得重复展开

**I. 章末钩子有效性**（番茄读者留存命脉，单独一项校验）
- 钩子是否落在最后一段？（不能被收束语/抒情段稀释——读者翻完最后一句应停在悬念点上）
- 钩子类型是否与本章节奏匹配？（高潮章用悬念/反转钩，铺垫章用预警/期待钩，卷尾/弧尾用结构钩）
- 钩子信息是否前 5 章未重复？（连续两章用同类钩 = 钝化；上一章刚用信息钩收尾，本章就换一种钩子）

**J. 章节标题与文件名校验**（番茄平台限制 + 工程一致性）
- 章节标题不少于 2 个汉字（番茄平台单字标题会拒）
- 章节标题在已写章节中是否唯一？用 `grep "^title:" novel/chapters/*.md` 核查不重名（番茄不接受同名章节）
- frontmatter 的 `word_count` 是否已用 `wc -m` 实测后回填？（不可估算）
- 文件命名是否符合 `v{卷号两位}_c{章号三位}.md` 格式

**K. 小说正文格式校验**
- 正文中是否出现 `---`、`—————`、`* * *` 或章内小节标题？→ 全部改成空行 + 时间/地点/动作自然转场
- 换场/换时段/换地点是否用了只含全角空格 `　` 的空白段形成软切场？普通段落是否仍只用 1 个空行？→ 调整空白层级，保持粘贴/预览后的读感清晰
- 正文中是否出现 `cXXX`、`BXX`、`伏笔#`、`log`、`状态文件`、`节拍` 等工程标记？→ 全部改成故事内叙述
- 备忘录/数据记录是否像角色真实会写的内容，而不是作者设定表？→ 如不自然，改成视角角色阅读、输入、删改的动作
- 是否出现大量连续一行段落？→ 合并同一动作链/心理链，保留少量单句段用于停顿、重音和章末钩子
