# 大内容生成协议 & 长篇管理策略

> 从 SKILL.md 拆出。所有命令在生成大量内容时参照本文件。

## 大内容生成协议

### 输出量控制
- **单次响应上限**：生成的文件内容不超过 **800 行**（约 20000 字符）
- **超限自动分段**：预估输出超过上限时，必须拆分为多次文件写入
- **逐段写入**：每完成一段就立即写入/追加到文件，不在内存中累积全文
- **段间无需确认**：分段是技术手段，对用户透明，自动连续执行

### 适用场景
| 命令 | 典型超限情况 | 分段策略 |
|------|-------------|---------|
| outline volume N | 40-50章详细大纲 | 框架→逐段详写→收尾（三阶段） |
| write | 单章一般不超限 | 超4000字时分场景写入 |
| review | 多章审查报告 | 每10章一份报告 |
| check | 全面一致性检查 | 按检查类别分批输出 |
| recap | 卷级摘要 | 一般不超限 |

### 断点恢复
- 每次写入文件后，当前进度已持久化
- 如果中途断开，重新开始时读取已写入的文件，从断点处继续
- 不需要从头重新生成

## 长篇管理策略（10万字+）

### 分卷管理
- 每卷有独立大纲，但服从总大纲
- 每卷有明确的开始和结束
- 卷与卷之间有承上启下

### 连贯性日志分级
- **章级日志**：每章关键事件（在 continuity/log.md）
- **卷级摘要**：每卷结束后生成卷摘要（在 outline/volume_XX.md 末尾追加）
- **角色状态快照**：每 50 章做一次角色全状态快照

### 日志分层管理（log.md 双区结构 + log_archive/）

#### 1. log.md 双区结构
- **顶部 = 已完成单元摘要区**：每个已完结案件/故事弧一条摘要（3-5行），包含时间跨度、核心事件链、关键伏笔状态
- **底部 = 最近10章详细记录区**：仅保留最近10章的完整章节记录
- **排序规则**：最近章节区按**章号降序**排列，最新章在最上方。每写完新章立即插入到 `## 最近章节详细记录区` 标题正下方

#### 2. 单元完结归档流程
当一个故事单元/案件弧完成时：
1. 运行 `/novel recap` 生成该单元的3-5行压缩摘要
2. 将摘要添加到 `log.md` 顶部的"已完成单元摘要"区
3. 将该单元的详细章节记录移入 `continuity/log_archive/`
4. 归档文件命名：`v01_unit1_jiumian.md`、`v01_unit2_xxx.md`，以此类推

#### 2.5 归档摘要 5 必填字段标准

> 单元摘要、10 章批次归档摘要、卷摘要的统一字段。新写归档摘要时必须按此结构，避免每次格式漂移。

每条摘要必须包含以下 5 个字段（无内容时也要明确标"无"+原因）：

```
### cXXX-cYYY（关键词，3-5 个标签用 + 分隔）→ 归档 `log_archive/v0X_cXXX-cYYY.md`
- **时间跨度**：YYYY 年 M 月 D 日（周X）— YYYY 年 M 月 D 日（周X）
  ↑ 必须绝对日期+周几，禁止"某周三"这种相对说法
- **核心事件链**：事件 A → 事件 B → 事件 C → 事件 D（单行 80-200 字符，→ 串联因果）
  ↑ 提取主干因果链，不展开心理活动细节
- **关键设定确立**：本单元首次锁定的硬数据/地名/人物属性/价格/距离/时间常量
  ↑ 凡是写入正文形成"锁"的细节都要列出，便于后续查找
- **主线递进**（项目专属字段，按项目调整名称，如“觉醒线推进”）：本单元所有触发的链组节点+编号+归因
  ↑ 项目无觉醒线则改为"核心爽点/情感转折"等同位字段
- **未闭合线索**：本单元埋下且未在本单元内回收的伏笔/约定/钩子，及其下一节点章号
  ↑ 不写"已闭合"的，只写仍 OPEN/PARTIAL 的，便于跨单元回查
```

**字段最小数限制**：每个字段至少 1 行，不可省略；如本单元未触发某字段（如"未推进觉醒线"），写"未植入·原因：……"。

**字段最大长度建议**：单条摘要总长 6-10 行，超出则压缩"核心事件链"的细节描述。

#### 3. 写新章时的加载策略
- **Tier 1 必读**：`log.md` 摘要区 + 最近 3 章详细记录
- **按需读**：`log_archive/` 中的归档文件——仅在需要跨单元回溯时

#### 4. 每10章修剪检查
每写完第 10/20/30... 章时，检查 `log.md` 底部详细记录是否超过10章：
- 如果超过，将最早的详细记录移入 `log_archive/`
- 始终只保留最近10章的详细记录在 `log.md` 中

#### 5. 归档文件命名规范
按卷和案件单元命名：`v{卷号}_unit{序号}_{案件拼音简称}.md`
- `v01_unit1_jiumian.md` — 第一卷·旧面具案
- `v02_unit1_xxx.md` — 第二卷第一个案件
- 跨单元但未满一个完整弧的章节，按10章批次归档：`v01_c001-c010.md`

### 伏笔文件分层管理（foreshadowing.md + foreshadowing_archive/）

伏笔跨卷存在（V01 埋→V05 收），不能按卷简单切割。采用"活跃索引 + 分卷归档"架构：

#### 1. foreshadowing.md（主文件，始终 Tier 1 加载）保留：
- **核心设定锁定区**（永驻）
- **时序修复表**（永驻，条目少）
- **硬种子待埋清单**（逐渐缩短，全埋完后可删）
- **链式伏笔进度区**（紧凑可视化条）
- **全局活跃索引**——所有 OPEN/PARTIAL 伏笔的**一行摘要**：`| ID | 描述 | 状态 | 埋设卷/章 | 预计回收卷 |`
  - 无论哪卷埋的，只要未 CLOSED 就留在主文件
  - 每条限一行，不含详细描述

#### 2. foreshadowing_archive/v01.md、v02.md…保留：
- 该卷**所有 CLOSED 伏笔**的完整记录（首次出现章节、具体文本、关联角色、回收过程）
- 该卷**埋设伏笔的详细描述**（即便仍 OPEN，详细描述也归档到埋设卷文件中，主文件只留一行索引）

#### 3. 写章时的加载策略
- **Tier 1 必读**：`foreshadowing.md` 主文件（锁定区 + 活跃索引 + 硬种子清单）
- **Tier 3 按需**：需要某条伏笔完整细节时（如回收 V01 的 F03），加载 `foreshadowing_archive/v01.md` 定位该条目

#### 4. 每卷完结时的归档流程
1. 将本卷所有 CLOSED 伏笔的完整记录移入 `foreshadowing_archive/vXX.md`
2. 将本卷埋设的 OPEN/PARTIAL 伏笔的详细描述也移入归档（主文件只保留一行索引）
3. 主文件瘦身后验证：活跃索引总行数、锁定区完整性

#### 5. 触发条件
- **首次触发**：开始写 V02 c001 时——V01 的 CLOSED 伏笔做首次归档
- **后续**：每卷 c001 开写前自动检查并执行归档
- **紧急触发**：`foreshadowing.md` 超过 300 行时，无论卷进度如何都立即归档

### 定期维护
- 每写完一卷，做一次全面一致性检查
- 每 10 章检查 `log.md` 是否需要修剪
- 每 10 章检查节拍表偏差（≥5 章 → `outline sync`；连续 5+ 个"铺垫"无"爽点" → 节奏塌陷预警）
- 每 50 章做一次角色全状态快照
- 每个角色的状态文件定期同步
