# outline 命令详细规则

> 从 SKILL.md 拆出。仅在 `/novel outline` 系列命令触发时加载。

## 大纲三阶段流程（`volume N`触发时自动执行）

一卷大纲（40-50章）的详细描述通常超过 1500 行，**禁止在单次响应中一次性生成**。必须分三个阶段：

**阶段一：框架**（写入文件头部）
- 卷头信息（章数、字数、故事时间、核心弧线、主角状态）
- **节拍进度表**（见下方格式）——既是节奏规划，也是写作进度追踪器
- 分段概要（每段 3-5 行：时间跨度、核心任务、节奏定位）
- 伏笔规划表：本卷需回收/推进/新埋的伏笔清单
- 新增角色预告

完成后**立即写入文件**，然后**自动进入阶段二**。

**阶段二：逐段详写**（追加到文件，格式见 [volume_outline_template.md](../templates/volume_outline_template.md)）
- 按段落顺序，每次写一段（≤10章）的详细章节描述
- 每章用 `#### cXX [章名]` 标题，包含 5 个固定字段：时间、核心事件、场景（5-10行）、章末钩子、伏笔（可选）
- 每章 **8-15 行**，禁止超过 20 行——超出说明场景描述太细，应压缩为要点
- 每段写完后**立即追加到文件**，不在内存中累积
- 段与段之间无需用户确认，自动连续写入
- 如果单段生成仍然过长（>8章且每章描述 >15行），进一步拆分为 5+5

**阶段三：收尾**（追加到文件末尾）
- 伏笔清单（本卷埋设/回收/推进的所有伏笔）
- 角色状态追踪（本卷末各角色状态）
- 节奏审计（高潮点、紧张度分布、温情点、信息量、低谷-积蓄-爆发循环）

完成后更新 `stats.md` 和 `foreshadowing.md`。

## 大纲上下文加载协议

写卷大纲前**必须**加载以下文件（类似 write 命令的 Tier 系统）：

**Tier 1 — 必读**：
- `novel/outline/structure.md`：总体结构和本卷规划
- `novel/continuity/foreshadowing.md`：所有 OPEN/PARTIAL 伏笔
- `novel/world/timeline.md`：世界观时间线中本卷对应年份
- `novel/world/power_system.md`：本卷涉及的力量/能力阶段
- 前一卷大纲的**最后一段 + 伏笔清单 + 角色状态追踪**（衔接用）

**Tier 2 — 规划后加载**：
- `novel/world/geography.md`：规划章节场景地点时，核对已有地名、距离、空间关系
- `novel/world/factions.md`：涉及多势力时
- `novel/characters/_index.md`：角色关系和出场规划
- 本卷新增角色的 yaml 文件（如已创建）

**Tier 3 — 按需加载**：
- 更早卷的大纲（需要回溯伏笔细节时）
- `novel/world/rules.md`

## 大纲质量检查清单

每卷大纲完成后逐项过：

- [ ] 时间线连贯：本卷起止时间与前卷衔接，内部月份递进无跳跃
- [ ] 能力成长合理：主角实力提升有足够铺垫（瓶颈→积累→突破）
- [ ] 伏笔全覆盖：foreshadowing.md 中所有计划在本卷回收的伏笔都已安排
- [ ] 新伏笔有锚点：新埋的伏笔标注了计划回收卷
- [ ] 爽点密度达标：每10章至少1个大爽点，每5章至少1个中爽点
- [ ] 章末钩子无遗漏：每章都有明确的钩子设计
- [ ] 角色弧线完整：每个出场角色在本卷有可追踪的变化
- [ ] 前卷交接干净：前卷末的悬念/钩子在本卷前3章有回应
- [ ] 与 structure.md 一致：核心事件和主角状态与总规划匹配

**创建大纲时必须包含：**
- 每卷的核心冲突和解决
- 每卷的爽点节奏设计（低谷→积蓄→爆发→奖励循环）
- 每个大节点的伏笔布局
- 角色成长曲线标注

**大纲模板参考**
- 总体结构（structure.md）：[templates/outline_template.md](../templates/outline_template.md)
- **卷大纲（volume_XX.md）**：[templates/volume_outline_template.md](../templates/volume_outline_template.md) ← 所有卷大纲必须遵循此骨架

## 节拍进度表（防漂移核心机制）

每卷大纲**头部**必须维护一张节拍表——写作时的实际对照物，替代刚性逐章规划：

```
| # | 节拍 | 弧线 | 节奏 | 预估 | 实际 | 状态 |
|---|------|------|------|------|------|------|
| B01 | 抵达小镇+异常信号建立 | 旧面具 | 铺垫 | c01-03 | c001-003 | ✅ |
| B02 | 面具失踪+第一起怪事 | 旧面具 | 爽点 | c04-06 | c004-006 | ✅ |
| B03 | 调查+真相第一层 | 旧面具 | 升级 | c07-10 | — | 待写 |
```

**列说明：**
- **节拍**：一个不可再分的故事事件（通常跨 1-3 章，最多 5 章）
- **弧线**：所属案件/故事弧（旧面具案、码头案、终局……）
- **节奏**：铺垫→升级→爽点→高潮→收束，确保节奏曲线不塌
- **预估**：创建大纲时的章号范围预期
- **实际**：写完后填入真实章号——**这是防漂移的关键字段**
- **状态**：✅ 已写 / 🔄 进行中 / 待写

**与逐章详细描述的关系：**
- 节拍表是"索引"（~30行），逐章描述是"正文"（数百行）
- 写作时 Tier 1 只加载节拍表；需要某个节拍的细节时，按该节拍的预估/实际章号定位到逐章描述段落
- 逐章描述中的章号允许随写作漂移，但节拍表的"实际"列始终反映真实进度

**`outline sync N` 做什么：**
1. 读取第 N 卷所有已写章节的 log 记录
2. 将每章实际内容匹配到大纲节拍
3. 生成/更新节拍表的"实际"列和"状态"列
4. 对未写节拍重新预估章节范围（基于已写部分的实际消耗速度）
5. 标记已失效的逐章描述（实际内容与原规划严重偏离的章节）
