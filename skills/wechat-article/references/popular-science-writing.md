# 科普型公众号写作

科普稿的目标不是“讲完知识”，而是让普通读者完成一次可复述、可验证、可迁移的认知变化。

## 1. 从谜题开始

把“介绍 X”改成答案不显然的具体问题。好谜题同时满足：

- 读者能看到场景，并会自然做出预测。
- 证据会推翻、修正或细化这个预测。
- 答案能引出一个可迁移的机制，而不只是冷知识。
- 这个机制会改变现实判断、选择或操作。

标题和首屏建立真实信息缺口；不要在开头交付完整答案，也不要故意藏住读者作决定所需的关键信息。

## 2. 建立知识脊柱

按认知顺序组织，不机械写成七个章节：

1. **现象**：真实场景、实验结果或矛盾。
2. **预测**：让读者先判断会发生什么。
3. **证据**：用一个关键对照揭晓结果。
4. **机制**：给出最短但完整的因果链。
5. **边界**：说明条件、例外和未知。
6. **迁移**：换个情境，让读者再判断一次。
7. **回环**：回到开头，展示读者现在如何重新理解同一现象。

每篇只保留一条主脊柱。支线知识如果不能帮助预测、解释或迁移，删除或另文处理。

## 3. 让概念在需要时出现

解释新概念时：

1. 先给熟悉的现象或具体例子。
2. 让读者看见旧解释哪里失效。
3. 此时才给概念命名。
4. 用 `A → B → C` 讲清因果。
5. 紧邻放一项证据、对照或可观察结果。
6. 说明机制在哪里不能外推。

一篇通常只教 3–5 个新概念。概念再多，读者得到的是“见过”，不是“学会”。

## 4. 用证据制造趣味

- 优先使用“提问 → 预测 → 揭晓”，少用“事实 → 列表 → 总结”。
- 至少安排一次有效参与：先猜后看、一分钟实验、换题迁移或错误诊断。
- 参与必须帮助学习；“欢迎留言”不是学习设计。
- 趣味来自现实与直觉的错位，不来自段子密度。
- 故事服务机制：删掉机制后，故事应失去被讲述的理由。

### 把知识写出人的温度

- 用一个可持续推进的场景、动作或困境承载知识，不用多个互不相干的小例子拼盘。
- 把读者放进判断发生的那一秒：他看见什么、先猜什么、哪里开始不安，随后才给术语。
- 允许叙述有停顿、误判和修正。科普不是把正确答案提前贴在每段门口。
- 文学性来自准确的细节、句子节奏和余味，不来自华丽形容词、拟人泛滥或伪造故事。
- 幽默必须兼任解释：若笑点不能暴露直觉错误、概念冲突或机制反差，删掉。

## 5. 例子、模型、比喻的顺序

优先级是：真实例子 → 简化模型或小图 → 必要时才用比喻。

比喻只解释一个关系，并紧接一句指出失效边界。不要把比喻推演成第二套世界观，更不要把“像什么”当成“为什么”。

## 6. 让数字替读者完成推理

每个数字都回答：

- 和谁比，条件是否可比？
- 差多少，能否直接算给读者？
- 改变什么，会影响时间、成本、风险还是成功率？

一个能改变理解的对照，胜过一张没有阅读任务的排行榜。

## 7. 选一种主结构

- **谜题—机制**：异常结果 → 预测 → 证据 → 机制 → 边界 → 用途。
- **系统之旅**：跟随一个对象穿过系统，每一站解决一个障碍。
- **误解—拆解**：常见说法 → 合理之处 → 反证 → 更好模型 → 适用边界。
- **问题—发明**：具体难题 → 旧方法失败 → 新概念诞生 → 今天仍付出的代价。

不要混用多套结构来追求“丰富”。

## 8. 双重验收

### 兴趣

- 标题和首屏提出了读者愿意猜、答案又不显然的问题。
- 正文至少有一次证据驱动的揭晓；复杂主题不强求戏剧化反转。
- 任意连续 500 字都在改变问题、证据或解释。
- 删掉俏皮话后，悬念和推进仍成立。
- 随机抽三段朗读，句式、段落收束方式和语气不能像同一模板复制。
- 至少有一处细节或意象在后文改变含义，形成回声，而不是一次性装饰。

### 学习

- 普通读者能在 30 秒内不用原文术语复述核心机制。
- 文章明确说明“因为 A，所以 B，进而 C”，没有把相关性写成因果。
- 关键机制附近有例子、对照或数据。
- 证据强度、适用条件、例外和未知处写清楚。
- 读者能用新模型解释另一个情境，或完成一个小验证。

任何一项失败，都回到问题和结构层重写，不靠多加形容词补救。

## 9. 常见失败

- 开头先列“本文三点结论”，杀死探索动力。
- 按官方文档顺序介绍功能，像换了口吻的说明书。
- 表格太早出现，读者不知道该看哪一列。
- 用更多事实掩盖没有核心问题。
- 只有故事没有机制，或只有类比没有边界。
- 把每节写成独立知识点，全文没有一条因果主线。
- 结尾突然给购买、职业或人生建议，忘了回答开头的问题。
