# 让配音更像真人：文本控制、挑版本、后期

## 1. 先改稿，再调模型
自然度一半来自文本。写给耳朵听：
- 短句为主，一句不超过约 20 字；长句拆开，用逗号给出换气点。
- 口语化：用“你”，少用书面连接词（“然而”“因此”“综上所述”）。
- 数字和年份写成要念的样子：“公元前 399 年”可以，“前399”会被念怪；“2400 年前”最好写成“两千四百年前”。
- 书名号、引号会被自动去掉（念出来会怪），不影响字幕显示。字幕用 `text`，配音用 `voiceText`，两者可以不同。

## 2. 控制标记（写在 voiceText 里）
| 需求 | 写法 | 例 |
|---|---|---|
| 呼吸、换气 | `[breath]` | `他本可以逃走，[breath]却选择留下。` |
| 多音字纠音 | **用拼音替换掉这个字**（字本身要删掉）：`[声母][韵母+声调]` | `给予` → `[j][ǐ]予`；`处死` → `[ch][ǔ]死` |
| 笑 | `[laughter]` | 轻松的段落里慎用 |
| 强调 | 把词单独成句或前面加停顿，比如“真的，是这样吗？” | 比加标记更稳 |

⚠️ 字和拼音同时保留（例如写成 `处[ch][ǔ]死`）会被**念两遍**（实测踩过）。另外，常用词里的多音字模型基本都能读对（如“判处”“处死”），**先试听，确认读错了再纠音**，不要预防性地加。

**外国译名的第一个字是常用单字词时**（爱、可、安、比、阿……），模型会把它当成一个词念、后面顿开。voiceText 里换成同音但不成词的字（爱 → 艾），字幕照写通行译名。

### 断句：逗号不一定管用
字一个没错、意思却全变了的断句错，根因多在文本：**逗号两边能连成另一个词或另一种结构时，模型会无视逗号，按词连读**。按句生成只保证**句号**处一定停，句中的逗号只是“建议”。
| 原文 | 被读成 | 改法 |
|---|---|---|
| 他是个奴隶，主人扭他的腿。 | 他是个奴隶主人，扭他的腿 | 拆成两句：`他是个奴隶。主人扭他的腿。` |
| 是挑好弓，瞄准，拉满 | 是挑好，弓 | 加量词消歧：`挑一张好弓` |
| 可能选的其实不多（本意“可，能选的”） | 可能 / 选的 | 换词：`可是，能选的其实不多。` |
| 那就是躲进了城堡，里面藏着逃避 | 城堡里面 / 藏着逃避 | `躲进了城堡。里面，藏着逃避。` |

**标点要落在韵律短语上，不是只看语法**（中文 TTS 的通行做法也是先按短语切、再按标点切）。要两头兼顾：
- **意思完了才用句号**：句号会让语调收住、下一句重新起调。一个意思没说完就打句号（例如同一句引语中间），会听成“突然断开”，改用分号或逗号连读。
- **不要碎成短句**：8 个字以内单独成句容易读得生硬、一顿一顿（“回头看这几个比喻。”→ 并成“回头看这几个比喻：第一个……”）。有意的短句可以留，但一段里别连着好几个。
- **一个连贯的动作中间不打逗号**：“他去了北方的一座小城，接着教书”会被读成两截，应为“去了北方的一座小城接着教书”。逗号放在真正换气的地方：主语长时的主谓之间、并列分句之间、转折之前。

写稿时**逐个逗号读一遍，把逗号前后两三个字连起来念**，能连成别的词（奴隶主、可能、城堡里面）或别的结构，就改成句号或换词。真正要停的地方用句号，不要依赖句中的 `｜`：`｜` 只有落在模型自然的停顿上才能拉长，落不上就会被跳过。

三个脚本配合使用：
- **配音前：文本自查** `python3 scripts/text_check.py script.json`：列出短句单独成句、逗号后只剩很短的尾巴，逐条读出声判断；它只提示不改稿。看过决定保留的句子原样写进 segments 文件的 `"textCheckOk": [...]`，以后不再提示。
- **配音后：断句自查** `python3 scripts/pause_check.py <配音目录>`：按能量找句中停顿，换算成“读到第几个字”，报出句中多停（把词拆开）、停顿挪位、连停两次、结尾被截断。它只抓“真的停错了”的句子；没有静音、只是语调把两个词连成一个的错（“奴隶主人”）抓不到，要靠写稿时避开和用户试听。
- **换版：** `python3 scripts/retake.py --segments script.json --out <配音目录> --only s4:4,s21:6 --takes 4`：给报出来的句子另出几个版本，自动挑检查没报问题、语速最接近全片中位数的那一版换进去（原文件备份为 .bak.wav）。

常见易错字要先查一遍：处（chǔ 死 / chù 所）、为（wèi 了 / wéi 人）、得（děi 去 / de）、行（háng 业）、重（chóng 新）、曾（zēng 祖 / céng 经）、朝（cháo 代）、载（zǎi 记载）、塞（sài 边塞）。外国人名的译名（苏格拉底、柏拉图等）通常念得对，但生僻译名要试听。

## 3. 语气指令（instruct）
segments 里给某一段加 `"instruct"`，或者命令行加 `--instruct`。用自然语言描述，比如：
- “请用低沉、缓慢、带一点悬念的语气讲述”（开场钩子）
- “请用轻松、带一点笑意的语气说”（冷知识、自嘲）
- “请用坚定、稍快的语气说”（高潮、转折）
- “请放慢语速，一字一顿地说”（结尾提问）

instruct 模式对音色的贴合度略低于零样本模式，只给需要特殊语气的几段加，不要全篇加。

## 4. 多版本挑选
`--only s14 --takes 3` 会生成 `seg_s14_t1/t2/t3.wav`。把它们拼成对比文件交给用户：
```bash
ffmpeg -i t1.wav -i t2.wav -i t3.wav -filter_complex "anullsrc=r=24000:cl=mono,atrim=0:0.8[g];[0][g][1][g][2]concat=n=5:v=0:a=1" cmp.wav
```
选定后，把选中的那个版本复制成 `seg_s14.wav`。种子是固定的，同一个 take 编号每次生成的结果都一样。

## 5. 人声后期（ffmpeg 滤镜链）
```
highpass=f=75,acompressor=threshold=-20dB:ratio=2.5:attack=8:release=160:makeup=2,equalizer=f=180:t=q:w=1:g=1.5,equalizer=f=3200:t=q:w=1.2:g=1.5
```
依次是：去低频嗡声 → 轻度压缩，让音量更稳定 → 180 Hz 增加温暖感 → 3.2 kHz 提升清晰度。成片交付前统一响度，用 `loudnorm=I=-16:TP=-1.5`（B 站和 YouTube 大约是 -14 到 -16 LUFS）。

## 6. 质检
- 脚本会打印每句的“字/s”：中文讲述正常约 3.5–5 字/s；低于 2.8 或高于 6.5 时，大概率是吞字、重复或卡住。
- **句末单字容易念糊**：例如“都会说我。”，模型可能在“说”后停顿约半秒，再出一声含混的音。改措辞让单字不落在句末（“都会用我来称呼自己。”）。
- 引号、书名号由脚本自动去掉，不用在 voiceText 里手动删。
- 配音前把可能读错的字（多音字、生僻译名，如“忒修斯”的忒 tè、“浸透”的浸 jìn）列给用户，确认读错了再用拼音替换。
- **按音色维护一张“实测读错表”**：用户试听确认读错的字词记下来（字词 / 读成 / 正确 / 纠音写法），下次写稿时直接纠音，不必等试听。同一个模型和音色，读错往往会重复出现，例如“事业”被读成 chì 业，写成 `[sh][ì]业`。表外的常用词仍然先试听再纠音，不要预防性地加拼音。
- **听写自查**（`python3 scripts/listen_check.py <配音目录>`，配完音就跑，整期约 10 秒）：用 macOS 26 自带的离线语音识别（SpeechAnalyzer，中文模型系统已带，不用下载）把每句配音转写出来，和台词按拼音逐句比对。⚠️ 是字音对不上的句子（漏字、多字、整词读错），列给用户重点听；“只差声调”多半是识别器猜字，顺带一提即可。数字、“的/地/得”已做归一。**局限**：识别器会按上下文自动纠正，同音或近音的读错（“事”读成 chì）不一定抓得到，所以它只是缩小试听范围，不能代替用户试听。需要 macOS 26+ 和 Xcode 命令行工具（首次运行会用 swiftc 把 `scripts/asr.swift` 编译到 `$VOICE_CLONE_HOME/bin/asr`）；比对需要 `pip install pypinyin`。
- 你听不到声音。交付前请用户重点听：多音字、专有名词、每段结尾有没有被截断、段与段之间语气是否连贯。
