# 项目清理

原则只有一条：**没用的删，有用的留。**“有用”指以后还会用到、或者删了要付出代价才能找回：正在用的流水线的输入、已发布版本的符号文件、会反复使用的环境（比如模拟器）。“没用”指被新版取代的产物、能自动重建的缓存、误生成的垃圾文件。

清理是不可逆操作，大多数被删的东西都不在 git 里。所以顺序固定：**盘点 → 分类 → 查引用 → 确认 → 删除 → 报告**，不要边看边删。

## 1. 盘点：项目和它背后的工具都要看

项目目录往往不大，真正占空间的是工具链的全局缓存。两边都量：

```bash
python3 <本skill目录>/scripts/scan.py <项目目录>
```

脚本只读，会列出：项目里最大的目录、被 git 忽略或未跟踪的大文件（这些删了**无法从 git 恢复**）、根目录下可疑的零碎文件（如 `:-`、`nohup.out`，多是重定向写错生成的），以及按项目类型探测到的全局缓存和磁盘剩余空间。

剩余空间要告诉用户：空间充裕时，大块但有用的东西就不值得冒险动。

## 2. 分类

每个候选项归到四类之一，判断依据见 [references/ecosystems.md](references/ecosystems.md)：

| 类别 | 例子 | 处理 |
|---|---|---|
| 可自动重建的缓存 | DerivedData、node_modules、`__pycache__`、`target/`、`.gradle` | 可删；说明代价（首次编译变慢、要重新下载） |
| 被取代的旧产物 | 旧版截图 / 海报、旧安装包、没提交的中间构建 | 可删；先确认新版已经齐全 |
| 会复用或有留存价值 | 模拟器、已提交版本的 Archive / dSYM、当前流水线的原始素材 | **保留**；只删其中确定废弃的个体 |
| 不可再生的原件 | 用户手工制作的素材、录音、数据、唯一一份的设计稿 | 保留；拿不准就问 |

几条容易判错的：

- **被 git 忽略 ≠ 没用。** 忽略只说明不进版本库，很多生成产物的输入（背景图、原始截图）也被忽略了。
- **旧版目录里可能有新版的输入。** 删整个 `v3/` 之前，看新版脚本和 README 有没有引用它的子目录。
- **已发布版本的构建要留。** 用来符号化崩溃日志；同一版本号下没提交的构建可以删。哪个是实际提交的，查项目的发布记录或问用户，不要按日期猜。
- **模拟器 / 虚拟机是复用环境。** 里面的数据大多是系统自己生成的，抹掉后启动又会长回来，还会丢测试状态，省不了多少空间。只删确定不再用的机型或运行时（`xcrun simctl delete unavailable`）。
- **不是这个项目的东西别顺手删。** 全局缓存里常混着其他项目的产物（别的 app 的 Archive），不确定的就列出来，交给用户决定。

## 3. 查引用

删任何目录前，在**已跟踪的文件**里搜它的路径：

```bash
git grep -n "<目录名>"
```

有引用的分两种情况：

- 引用它的脚本也已经废弃（只服务于旧版产物），就把脚本一起删，并改掉 README 里的说明，不要留下指向空目录的死链接；
- 引用它的是当前在用的流水线，就保留。

## 4. 确认

用一张清单向用户确认，每项写清楚：路径、大小、为什么能删、删了的代价、保留了什么。按上表把“建议删”和“建议留”分开写，用户可以多选。项目外的全局缓存要单独列一组，因为它们影响所有项目。

用户确认过的范围才动。之后用户说“没用的都可以删”，就按本节的分类自己判断执行，但会复用的和不属于本项目的东西仍然不动。

## 5. 删除

- 用**绝对路径**逐个删，不要 `cd` 之后再用相对路径加通配符；一条命令里写清每个目标。
- 能放进废纸篓就优先放进去，方便用户恢复（Xcode Archive 例外，见 [references/ecosystems.md](references/ecosystems.md)）。
- git 跟踪的文件用 `git rm`，改动作为一次独立提交，提交信息说明删了什么、为什么。
- 删除项目外的目录（全局缓存）时，agent 的安全检查可能会拦下。被拦下就停，不要换个写法绕过去；把要删的东西、原因和一条可以直接运行的命令交给用户。
- 删之前确认相关工具没在运行（比如 Xcode 在编译时不要删 DerivedData）；正在排查的 bug 还没定位时，也不要清缓存，免得把证据一起删掉。

## 6. 报告

- 前后大小对比（`du -sh`）和释放的总量；
- 删了什么、留了什么，各一句原因；
- 被拦下或留给用户的项目，附上命令；
- 删掉后已经失效、需要用户决定的东西（比如还引用着已删目录的旧脚本）。

`git status` 要保持干净或只剩这次的改动，确认没误删跟踪文件。
